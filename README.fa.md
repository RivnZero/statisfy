# statisfy

[English](README.md) | **فارسی**

استاتیس‌فای (statisfy) یک ابزار خط فرمان برای دیدن وضعیت واقعی ابزارهای کدنویسی هوش مصنوعی روی سیستم شماست: پلن اشتراک، سهمیه‌ها، محدودیت نرخ، محدودیت نشست، مصرف توکن و هزینه‌ها — همه در یک دستور.

```text
$ statisfy

AI CODING
────────────────────────────────────────────

Codex       Plus
Weekly      ██████████  96% left · reset 5d 13h

Claude      Pro

OpenCode
Today       294.8K tokens
Cost        $0.00
Sessions    4
```

## چرا استاتیس‌فای؟

اگر از چند ابزار کدنویسی هوش مصنوعی استفاده می‌کنید، هر کدام پنل یا دستور مخصوص خودش را دارد و باید یکی‌یکی بررسی‌شان کنید. استاتیس‌فای این‌ها را در یک داشبورد جمع می‌کند — فقط با اطلاعاتی که واقعاً می‌تواند تشخیص دهد.

**بدون داده جعلی. بدون ابزار در دسترس‌نبوده. بدون متریک خالی.**

استاتیس‌فای فقط مقادیری را نشان می‌دهد که واقعاً قابل تشخیص هستند. اگر ابزاری نصب یا تنظیم نشده باشد، از داشبورد اصلی حذف می‌شود. اگر مقداری قابل تشخیص نباشد، نمایش داده نمی‌شود — هیچ‌وقت حدس زده نمی‌شود.

## نصب

```bash
go install github.com/RivnZero/statisfy/cmd/statisfy@latest
```

یا باینری سیستمتان را از بخش release دانلود کنید.

## دستورها

| دستور | توضیح |
|---|---|
| `statisfy` | داشبورد ابزارهای در دسترس |
| `statisfy <tool>` | جزئیات یک ابزار خاص |
| `statisfy --json` | خروجی JSON نرمال‌شده و قابل خواندن برای ماشین |
| `statisfy --refresh` | نادیده گرفتن کش و دریافت اطلاعات تازه |
| `statisfy --all` | نمایش ابزارهایی که در حال حاضر در دسترس نیستند |
| `statisfy doctor` | تشخیص مشکلات نصب/تنظیم/احراز هویت |
| `statisfy sources` | نمایش اینکه هر مقدار از کجا آمده (منبع داده) |
| `statisfy watch` | داشبورد زنده با بازه‌های به‌روزرسانی (`q` برای خروج، `r` برای تازه‌سازی) |
| `statisfy version` | نمایش نسخه |

## ابزارهای پشتیبانی‌شده

| ابزار | منبع داده | پایداری |
|---|---|---|
| Codex | `codex app-server` (API رسمی) | داخلی |
| Claude | حالت محلی `~/.claude.json` | محلی |
| Gemini CLI | حالت محلی حساب گوگل | محلی |
| GitHub Copilot CLI | پایگاه داده محلی SQLite | محلی |
| Qwen Code | فایل تنظیمات محلی | محلی |
| OpenRouter (ارائه‌دهنده) | API رسمی `/api/v1/key` | مستند |
| Cline | فایل‌های محلی `taskHistory.json` | تجربی |
| Aider | لاگ تحلیلی محلی (اختیاری) | تجربی |
| Factory Droid | فایل تنظیمات محلی | مستند |
| OpenCode | پایگاه داده محلی SQLite | محلی |
| Freebuff | API سرویس‌دهنده | داخلی |

برخی یکپارچه‌سازی‌ها به رابط‌های داخلی یا مشاهده‌شده توسط جامعه وابسته‌اند و ممکن است با تغییر ابزارهای بالادستی نیاز به اصلاح داشته باشند. این شفافیت بخشی از ارزش پروژه است — جدول کامل قابلیت‌ها و برچسب‌های پایداری در [README انگلیسی](README.md#supported-integrations) آمده است.

## پیکربندی (اختیاری)

استاتیس‌فای بدون هیچ فایل پیکربندی هم کار می‌کند. برای تغییر پیش‌فرض‌ها، فایل `config.toml` را در پوشه پیکربندی پلتفرم بسازید:

- لینوکس: `~/.config/statisfy/config.toml`
- مک: `~/Library/Application Support/statisfy/config.toml`
- ویندوز: `%APPDATA%\statisfy\config.toml`

```toml
cache_ttl = "5m"
timeout = "8s"
watch_interval = "10s"

[adapters.freebuff]
enabled = false
```

اولویت: **فلگ‌های خط فرمان > پیکربندی کاربر > پیش‌فرض‌ها**. فایل پیکربندی خراب هرگز بی‌صدا نادیده گرفته نمی‌شود — یک پیام خطای قابل فهم نمایش داده می‌شود.

## امنیت

استاتیس‌فای به‌گونه‌ای طراحی شده که صرفاً **مشاهده‌گر** باشد:

- هرگز اعتبارنامه‌ها را چاپ، لاگ، کش یا سریال‌سازی نمی‌کند.
- هرگز رفتار ابزار مورد بازرسی را تغییر نمی‌دهد؛ در حالی که یک نمونه از ابزار (مثل Freebuff) در حال اجراست، هیچ درخواست شبکه‌ای ارسال نمی‌کند.
- درخواست‌هایی که ممکن است تغییر حالت دهند، هرگز دوباره (retry) نمی‌شوند.
- فقط حداقل داده لازم را از حالت محلی ابزارها می‌خواند.

## خروجی JSON

```bash
statisfy --json
```

بدون ANSI و بدون اعتبارنامه. مقادیر ناشناخته حذف می‌شوند، نه به‌صورت فیلد خالی.

## محدودیت‌های شناخته‌شده

- Codex و Freebuff به رابط‌های داخلی وابسته‌اند که ممکن است بدون اطلاع تغییر کنند.
- Aider به‌صورت پیش‌فرض هیچ داده مصرفی ذخیره نمی‌کند؛ فقط با `--analytics-log` لاگ ایجاد می‌شود.
- Droid فقط مدل پیکربندی‌شده را گزارش می‌دهد؛ مصرف و اعتبار پشت API داخلی است که استاتیس‌فای عمداً آن را فراخوانی نمی‌کند.
